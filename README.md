# 콕집서 (KOKJIPSEO)

1인 가구를 위한 냉장고 관리 서비스의 Figma 프로토타입 구현입니다. React·TypeScript·Vite·pnpm을 사용하며 별도의 UI 컴포넌트 라이브러리는 사용하지 않습니다.

## 실행

검증 환경: Node.js 24.21 / pnpm 11.25. Node.js 22.12 이상 권장.

```sh
pnpm install
pnpm dev
pnpm build
pnpm preview
```

개발 주소: http://127.0.0.1:5173/

## 인터랙션

홈 CTA와 등록 메뉴는 등록 방식 화면으로 이동합니다. 홈에서 냉장고는 신규 사용자 냉장고 화면으로 이동합니다. 냉장고와 등록 화면의 홈 메뉴, 냉장고의 등록 CTA도 원본 연결대로 동작합니다. 화면 이동에는 Figma의 즉시 전환(transition: null)을 적용했습니다. 주소의 해시로 화면을 관리하며 브라우저 뒤로/앞으로 이동을 지원합니다.

`src/prototype/flow.ts`에 원본 목적지 ID를 보존했습니다. Figma 반응이 없는 필터·등록 방식 카드에는 임의 동작을 추가하지 않았습니다.

이번 범위는 홈·냉장고 신규 사용자·식재료 등록 방식까지입니다. 레시피와 마이페이지는 사용자 요청에 따라 제거했습니다. 하단 메뉴의 아이콘과 라벨은 유지하지만 두 메뉴는 비활성 상태입니다. 검색과 영수증 촬영 다음 단계의 원본 목적지는 보존했으며, 해당 화면도 이번 범위 밖이므로 버튼은 비활성 상태입니다.

## 초기 데이터

홈과 냉장고는 식재료 0개 상태입니다. 이전에 임의로 추가한 등록 폼, 저장 기능, 등록 목록, 완료 알림, 메뉴 안내 모달을 제거했습니다. 이전 브라우저 저장 키 `kokjipseo.ingredients.v1`도 앱 시작 시 삭제합니다. 새 식재료 데이터는 저장하지 않습니다.


## 구조

```text
src/
  App.tsx                  # 화면 구성과 해시 이동
  components/              # 공통 버튼, 헤더, 카드, 배너, 하단 내비게이션
  features/
    home/                  # 기본 빈 홈
    fridge/                # 신규 사용자 냉장고
    registration/          # 등록 방식 선택 화면
  prototype/flow.ts        # 확인된 원본 연결과 목적지
  assets/                  # Paperlogy 글꼴
  lib/assets.ts            # 배포 경로를 고려한 자산 URL
  styles/                  # Figma 토큰과 화면 CSS
public/assets/             # 원본 이미지·SVG
```

별도 디자인 시스템 링크는 제공되지 않았으므로 화면의 연결된 컴포넌트와 Variables·Styles 값을 기준으로 구성했습니다.

Paperlogy: [웹폰트 배포](https://github.com/whitedev7773/Paperlogy), [원본 배포 및 라이선스](https://freesentation.blog/paperlogyfont).

## 검증 및 배포

TypeScript 엄격 검사와 Vite 빌드, 390×844 화면 비교, 원본 자산 로딩·크기, 화면 이동, 초기 데이터 삭제를 확인했습니다.

`base: './'`와 자산 경로 헬퍼로 GitHub Pages의 저장소 하위 경로에 대응합니다. `dist/`가 배포 대상입니다. GitHub Actions 워크플로는 아직 추가하지 않았습니다.



## AI 인식 결과 추가 구현

작업 브랜치: `feature/yunjeong_ai-result_v1`.

- `/#5572:19525`: AI 인식 결과 확인 화면. Figma 원본의 8월 8일 토 / 오전 10:49, 대퍄·양파·두부·콩 예시를 사용합니다.
- 촬영 화면의 촬영/앨범 버튼은 네 항목의 표시 상태를 true로 초기화한 뒤 인식 결과로 이동합니다.
- 항목 삭제는 Figma `visible/item0..item3 = false`를 적용합니다. 확인 모달이나 영구 저장은 없습니다.
- 수정 버튼은 원본 `editing`과 `pendingName` 변수의 대상과 값을 설정합니다. 원본에 입력창 열기나 저장 액션이 연결되어 있지 않아 임의 팝업을 추가하지 않았습니다.
- 날짜/시간 수정과 도움말에는 실행 액션이 없습니다. 날짜·시간은 원본 예시를 표시하며 임의 편집 기능을 추가하지 않았습니다.
- 뒤로 가기는 원본 BACK 동작, 재촬영은 촬영 화면 이동입니다.
- 등록은 원본 목적지 `/#5572:19852` (냉장고 - 등록순)으로 이동합니다. 해당 화면의 고정 예시 목록도 구현했습니다. 프로토타입은 실제 인식 항목을 저장하는 액션이 없으므로 목록은 원본 예시이고 홈은 계속 빈 초기 상태입니다.
- 실제 AI/OCR API나 카메라·앨범 접근을 실행하는 기능은 포함하지 않습니다.

`src/features/recognition/`에 결과 화면과 프로토타입 상태를 분리했습니다. `src/styles/recognition.css`가 추가 화면 스타일입니다. 촬영 화면에서는 `onRecognize` 콜백만 연결했습니다.

## v2 편집 인터랙션

`feature/yunjeong_ai-result_v2`에서 v1의 기존 `visible`, `editing`, `pendingName` 및 삭제·재촬영·촬영/앨범 복원·뒤로·등록 연결을 유지하면서 편집 동작을 추가했습니다.

참고 프레임: `3265:8775`. 날짜 `5096:5586`, 시간 `5096:5585`는 중앙 오버레이와 바깥 클릭 닫기, 0.3초 전환을 적용했습니다. 사용자가 요청한 확인·취소 버튼을 추가했고 확인한 값만 반영합니다. 캘린더는 현재 값의 월을 열고 이전/다음 월과 실제 날짜 선택을 지원합니다. 시간은 시·분·AM/PM 선택과 키보드 접근을 지원합니다.

이름 수정은 연필 버튼을 누르면 목록 안의 현재 이름을 직접 편집합니다. 별도 모달 없이 실제 입력에 포커스를 주어 모바일 기본 키보드를 사용합니다. 키보드 완료/Enter 또는 입력 영역 밖 클릭으로 반영하며 해당 항목의 인식오류 표시를 제거합니다. Escape로 취소하면 기존 이름과 오류 상태를 유지하고, 빈 이름도 반영하지 않습니다. Figma의 `5513:3767` 시스템 키보드와 텍스트 직접 편집 주석을 따른 동작입니다.

도움말 `5469:19213`은 원본의 안내 바텀시트로 연결했습니다. 확인 버튼으로 닫으며 바깥 클릭으로는 닫히지 않습니다.

편집 값은 현재 실행 중인 앱의 상태로 유지합니다. 새로고침 후에는 원본 예시로 초기화하며 서버·브라우저 영구 저장은 추가하지 않았습니다. 등록 이후의 고정 예시 화면과 기존 등록 연결도 바꾸지 않았습니다.

검증: 날짜/시간 확인·취소, 이름 저장·재편집·취소, 삭제·재촬영 복원, 등록 이동, 도움말 닫기, 390×844 화면과 원본 자산, TypeScript 검사 및 빌드.
