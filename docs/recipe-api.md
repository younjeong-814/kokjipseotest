# 레시피 API · 검색 · 결과 화면

작업 범위: 담당 3번. `master`에 반영된 재료 선택(`RecipePage`), 빈 화면, 임박 재료 없음, 결과 없음 디자인을 재사용한다. 재료 선택 화면의 `onRecommend`로 선택한 ID를 보관하고 `/#recipe-no-result`에서 실제 API를 호출한다. 해당 경로는 검색 결과와 실제 0건 결과를 모두 표시한다.

## 실행 설정

1. 식품안전나라에서 API 인증키와 **조리식품의 레시피 DB(COOKRCP01)** 활용 승인을 받는다.
2. `.env.local`에 `FOOD_SAFETY_API_KEY=` 항목을 추가하고 등호 뒤에 키를 입력한다. `VITE_` 접두사를 붙이지 않는다. 기존 OCR 키와 `.env.example`은 수정하지 않는다.
3. `pnpm dev`를 다시 시작하고 `/#recipe`에서 냉장고 재료를 선택한 뒤 검색한다.

인증키는 Vite 개발/미리보기 서버에서만 읽으며 브라우저 응답·콘솔·클라이언트 번들로 보내지 않는다. 키가 없거나 이용 승인이 없으면 결과 없음 대신 설정 오류를 표시한다.

## 연동 계약

- `GET /api/recipes?ingredient=대파&ingredient=두부&page=1`
- 재료 1~10개, 각 60자 이하. 페이지는 1부터 시작하며 한 페이지에 20개를 반환한다.
- 성공: `{ recipes, total, page, pageSize }`. 실패: HTTP 오류 상태와 `{ error }`.
- `src/features/recipe/api.ts`의 `searchRecipes(names, page, signal)`이 프런트엔드 진입점이다.
- `RecipeResults`의 `ingredients`에 선택된 이름 배열을 전달한다. 검색 조건을 바꿀 때는 `key={JSON.stringify(names)}`로 새 검색 세션을 시작한다.
- 앱은 `selectionContext`로 선택된 원본 재료와 뒤로/다시 선택 콜백을 전달한다. 0건일 때만 `RecipeNoResultPage`를 표시하고, 검색 중이나 오류를 결과 없음으로 표시하지 않는다. 재료 선택으로 돌아오면 기존 선택을 유지한다.
- `onOpen(recipe)`를 전달하면 상세 보기 버튼이 나타난다. 상세 담당자는 `types.ts`의 `Recipe`를 그대로 사용할 수 있다(사진, 재료, 영양 정보, 조리 순서/이미지 포함).
- 재료 선택 연결에서는 상품명을 기존 분류 사전의 식재료 키워드로 변환하고 중복을 제거한다. 예: 상품명에 포함된 `두부`로 검색. API 자체는 전달된 이름으로 검색하므로 다른 선택 화면에서도 동일한 계약을 사용한다.

## 검색 기준과 상태

선택한 **모든** 재료가 재료 정보에 포함된 레시피를 찾는다(AND). 첫 재료로 공식 API 후보를 검색하고, 후보 페이지를 전부 받은 뒤 서버에서 나머지 재료를 필터링한다. 공백 차이와 계란/달걀 동의어를 처리한다. 재료명 부분문자열 검색이며 재료만으로 완성할 수 있다는 의미는 아니다. 추가 재료가 필요할 수 있음을 결과 목록에 안내한다.

후보는 최대 10,000건까지 처리하며 이를 초과하면 명시적인 검색 범위 오류를 반환한다. API 페이지당 1,000건, 요청 제한시간 15초, 재료별 캐시 5분/최대 20개, 동일 요청 병합으로 중복 호출을 줄인다. 캐시에는 성공 응답만 저장한다.

검색 전 안내, 선택 없음, 검색 중, 목록, 실제 결과 없음(`INFO-200` 또는 정상 응답의 0건), 인증/승인 오류, 호출 한도 오류, 통신/형식 오류, 다시 시도 및 이전/다음 페이지를 제공한다. 조건 변경·화면 이탈 시 브라우저 요청을 취소하고 이전 응답이 새 결과를 덮어쓰지 않게 한다.

## 배포 및 검증

정적 `dist/`만 호스팅하면 서버 API가 실행되지 않는다. 배포 시 `server/recipes.ts`를 Node 서버/서버리스 API로 연결하고 필요하면 `VITE_RECIPE_ENDPOINT`를 해당 `/api/recipes` 주소로 지정한다. 비밀 키는 배포 서버에만 설정한다.

`pnpm test`는 응답 매핑, 다중 재료 검색, 페이지 처리, 캐시, 중복 요청, 오류·결과 없음 분리, 입력 검증, 클라이언트 요청 계약을 검증한다. 인증키 없는 상태에서는 실제 인증 검색 성공까지 검증할 수 없다. 테스트의 응답 데이터는 테스트 파일에만 있으며 실제 UI에 예시 결과를 반환하지 않는다.

공식 명세: https://www.foodsafetykorea.go.kr/api/openApiInfo.do?menu_grp=MENU_GRP31&menu_no=661&show_cnt=10&start_idx=1&svc_no=COOKRCP01

## Figma 목록·상세 통합

현재 추천 버튼은 `/#recipe-results`로 연결됩니다. RecipeResults의 API 요청과 상태 처리를 유지하고 성공 응답을 RecipeResultsPage 카드에 표시합니다. 카드 선택은 실제 응답 Recipe를 상세 표시용 모델로 변환하여 `/#recipe-detail?recipe=ID`로 연결합니다. API 미제공 시간/난이도/인분을 추정하지 않습니다. 기존 `/#recipe-no-result` 경로도 API 연동 상태로 유지합니다.
