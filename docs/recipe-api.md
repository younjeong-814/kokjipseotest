# 레시피 API · 검색 · 결과 화면

작업 범위: 담당 3번. `master`에 반영된 재료 선택(`RecipePage`), 빈 화면, 임박 재료 없음, 결과 없음 디자인을 재사용한다. 재료 선택 화면의 `onRecommend`로 선택한 ID를 보관하고 `/#recipe-no-result`에서 실제 API를 호출한다. 해당 경로는 검색 결과와 실제 0건 결과를 모두 표시한다.

## 실행 설정

데이터 출처: 농림수산식품교육문화정보원 레시피 Open API (기본정보 `Grid_20150827000000000226_1`, 재료정보 `Grid_20150827000000000227_1`, 과정정보 `Grid_20150827000000000228_1`). 식품안전나라 COOKRCP01에는 조리 시간·난이도·인분이 없어 교체했다.

1. data.mafra.go.kr에서 회원가입 후 Open API 인증키를 발급받는다(공공데이터포털 15057205/15058981 페이지도 같은 기관 API로 연결된다).
2. `.env.local`에 `MAFRA_API_KEY=` 항목을 추가하고 등호 뒤에 키를 입력한다. `VITE_` 접두사를 붙이지 않는다. 기존 OCR 키와 `.env.example`은 수정하지 않는다. 기존 `FOOD_SAFETY_API_KEY`는 더 이상 쓰지 않는다.
3. `pnpm dev`를 다시 시작하고 `/#recipe`에서 냉장고 재료를 선택한 뒤 검색한다.

인증키는 Vite 개발/미리보기 서버에서만 읽으며 브라우저 응답·콘솔·클라이언트 번들로 보내지 않는다. 키가 없거나 잘못되면 결과 없음 대신 설정 오류를 표시한다.

## 연동 계약

- `GET /api/recipes?ingredient=대파&ingredient=두부&page=1`
- 재료 1~10개, 각 60자 이하. 페이지는 1부터 시작하며 한 페이지에 20개를 반환한다.
- 성공: `{ recipes, total, page, pageSize }`. 실패: HTTP 오류 상태와 `{ error }`.
- `src/features/recipe/api.ts`의 `searchRecipes(names, page, signal)`이 프런트엔드 진입점이다.
- `RecipeResults`의 `ingredients`에 선택된 이름 배열을 전달한다. 검색 조건을 바꿀 때는 `key={JSON.stringify(names)}`로 새 검색 세션을 시작한다.
- 앱은 `selectionContext`로 선택된 원본 재료와 뒤로/다시 선택 콜백을 전달한다. 0건일 때만 `RecipeNoResultPage`를 표시하고, 검색 중이나 오류를 결과 없음으로 표시하지 않는다. 재료 선택으로 돌아오면 기존 선택을 유지한다.
- `onOpen(recipe)`를 전달하면 상세 보기 버튼이 나타난다. 상세 담당자는 `types.ts`의 `Recipe`를 그대로 사용할 수 있다(사진, 재료, 영양 정보, 조리 순서/이미지 포함).
- 재료 선택 연결에서는 상품명을 기존 분류 사전의 식재료 키워드로 변환하고 중복을 제거한다. 예: 상품명에 포함된 `두부`로 검색. API 자체는 전달된 이름으로 검색하므로 다른 선택 화면에서도 동일한 계약을 사용한다.

## 검색 기준과 상태

전체 레시피가 약 500건이라 첫 검색 때 세 Grid를 모두(요청당 1,000건) 받아 `RECIPE_ID`로 합치고 서버 메모리에 12시간 캐시한다. 동시 요청은 하나로 병합하고 성공 응답만 캐시한다.

선택한 **모든** 재료가 재료명(`IRDNT_NM`)에 포함된 레시피를 찾는다(AND, 부분문자열, 공백 무시, 계란/달걀 동의어). 선택 재료가 주재료(`IRDNT_TY_NM`)로 쓰이는 레시피를 먼저 보여준다.

카드: 조리 시간(`COOKING_TIME`)·난이도(`LEVEL_NM`)를 API 값 그대로 표시한다. 태그는 레시피에 들어가는 선택 재료 + 선택하지 않은 재료 1개(주재료 > 부재료 > 양념 순). 상세: 인분(`QNT`), 재료별 분량(`IRDNT_CPCTY`), 조리 순서(`COOKING_NO` 순)를 표시한다. 이 API에는 탄수화물·단백질·지방·나트륨이 없고 칼로리만 있다.

검색 전 안내, 선택 없음, 검색 중, 목록, 실제 결과 없음(`INFO-200` 또는 0건), 인증 오류(`INFO-100`), 호출 한도(`ERROR-350`), 통신/형식 오류, 다시 시도 및 이전/다음 페이지를 제공한다.

주의: API 주소가 `http://211.237.50.150:7080`(HTTP 전용)이고 이미지 URL도 HTTP다. 서버 호출은 문제없지만 HTTPS로 배포하면 브라우저가 이미지를 막을 수 있어 이미지 프록시가 필요할 수 있다. 오래된 데이터라 깨진 이미지는 기본 이미지로 대체한다.

## 배포 및 검증

정적 `dist/`만 호스팅하면 서버 API가 실행되지 않는다. 배포 시 `server/recipes.ts`를 Node 서버/서버리스 API로 연결하고 필요하면 `VITE_RECIPE_ENDPOINT`를 해당 `/api/recipes` 주소로 지정한다. 비밀 키는 배포 서버에만 설정한다.

`pnpm test`는 응답 매핑, 다중 재료 검색, 페이지 처리, 캐시, 중복 요청, 오류·결과 없음 분리, 입력 검증, 클라이언트 요청 계약을 검증한다. 인증키 없는 상태에서는 실제 인증 검색 성공까지 검증할 수 없다. 테스트의 응답 데이터는 테스트 파일에만 있으며 실제 UI에 예시 결과를 반환하지 않는다.

## Figma 목록·상세 통합
