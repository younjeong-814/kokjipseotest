# 마이페이지 대시보드 데이터 연결

- 작업 브랜치: feature/yunjeong_mypage-dashboard_v1
- 디자인: Figma 3061:12938. 신규 사용자 화면(3061:13127)은 유지한다.
- 실제 화면: /#mypage. App에서 식재료(음식 제외) 개수를 registeredCount로 전달한다. 0개이면 기존 빈 화면, 1개 이상이면 대시보드를 표시한다.
- 디자인 확인: /#mypage?preview=1. Figma의 82점/78%/소비 12→18/폐기 5→2 등 예시를 사용한다. 사용자 통계나 localStorage에 저장하지 않는다.
- `MyPage`의 `reports?: MyPageReports`에 실제 집계 응답을 전달하면 주간/월간/전체 탭에 대응하는 값으로 표시한다. 계약은 src/features/mypage/report.ts 참고. React 상태/쿼리 훅에서 받은 reports를 전달하면 갱신된다.
- 미연동 점수·소비·폐기 값은 null이며 ‘—’/‘집계 중’으로 표시한다. 0은 실제 0으로 표시한다. 기록 없이 소비율과 관리 점수를 생성하지 않는다.
- `managedCount`는 선택한 집계 기준의 개수, managedLabel은 그 기준을 설명하는 문구다. 현재 기본값은 ‘현재 등록 현황’이다. 클릭 시 기존 냉장고 목록으로 이동한다.
- 동적 차트는 전달된 비율로 그리며 원본 차트 SVG는 디자인 예시에서 사용한다. 소비·폐기 이벤트 기록 및 점수 산식은 이번 범위에 포함하지 않는다.
- 기존 식재료 CRUD·레시피 API·키·저장 구조를 수정하지 않았다.

검증: 기존 테스트 188개 통과. 모바일 원본 자산 로드/크기, 예시 대시보드, 신규 빈 상태, 메모리 등록 4개→집계 중 표시, 기간 탭 전환을 확인했다. 테스트용 저장 데이터는 생성하지 않았다.

## 분석 데이터 부족 상태 (Figma 3061:13171)

등록 이력이 없으면 기존 신규 사용자 화면을 유지한다. 등록 항목은 있으나 선택 기간의 소비·폐기 완료 식재료 수가 3개 미만이면 차트 대신 데이터 부족 안내를 표시한다. API/집계 연결 시 MyPageReport.completedItemCount에 완료한 식재료 개수를 전달한다. 등록 개수나 g/ml 등 수량 합계를 대신 사용하지 않는다. 3개 이상이면 대시보드를 표시한다. 기존 계약 호환을 위해 completedItemCount가 없는 보고서는 score가 null인지로 준비 상태를 구분한다. 현재 소비·폐기 기록 기능은 아직 미연동이므로 기본 보고서는 0개로 처리한다.

미리보기: /#mypage?preview=insufficient. 원본 안내 이미지(350×170)와 아이콘(14×14), 주간/월간/전체 선택 및 등록 버튼 연결을 검증했다. 앞선 ‘집계 중 차트’ 설명은 이 데이터 부족 화면으로 대체한다.

표시 조건 보완: 등록 데이터가 있고 집계 보고서가 아직 전달되지 않은 경우 기본 대시보드를 표시합니다(미집계 수치는 —). 명시적으로 전달된 보고서가 분석 기준에 못 미칠 때만 데이터 부족 안내를 표시합니다. 소비·폐기 수를 모르는 상태를 0개로 간주해 대시보드 전체를 숨기지 않습니다.

실제 이력 연결: buildDashboardReports가 기존 loadHistory의 소비·폐기 기록을 읽어 주간(월요일 기준)·월간·전체 건수와 이전 기간 비교에 반영합니다. 완료 기록 3건 이상이면 대시보드를 표시합니다. 현재 보관 재료가 없어도 과거 기록이 있으면 신규 빈 화면으로 돌아가지 않습니다. 관리 점수와 등록 대비 소비율은 산식/등록 이력이 확정되지 않아 null을 유지합니다. 기존 기록 저장·삭제 분류는 변경하지 않습니다. 기간 경계·미래 기록 제외·3건 기준·삭제 후 이력 보존 집계를 포함해 테스트 200개 및 빌드가 통과했습니다.

소비율 연결: 선택 기간의 소비 완료 건수 ÷ (현재 보관 건수 + 같은 기간 소비·폐기 건수) × 100, 정수 반올림으로 표시합니다. 등록 6개에서 소비 2개·폐기 2개·보관 2개인 경우 33%입니다. 이력 없이 과거에 삭제한 항목은 복원할 수 없으며 별도 등록 로그가 없어 현재 저장 상태와 이력으로 관리 대상을 재구성합니다. 관리점수는 별도 미연동 상태를 유지합니다. 0/100%·빈 데이터·6개 사례를 포함해 테스트 203개 통과.

## 실제 이력 기반 계산 (2026-10-21)
- 고정 예시 점수/비율과 preview 쿼리 분기를 제거했다. 데이터가 적어도 계산 가능한 비율은 표시한다.
- 소비율: 선택 기간 관리 대상 중 일부 또는 전부 소비한 고유 식재료 수 / 관리 대상 수 × 100. 같은 식재료의 일부·완료 소비는 중복 집계하지 않는다.
- 관리 대상: 기간 중 보관한 적 있는 식재료. 기간 이전에 정리한 재료는 제외하고, 이월 보관 재료와 기간 중 소비·폐기한 재료는 포함한다. 음식은 제외한다.
- 관리율: 기간 중 상태 또는 보관 위치를 변경한 고유 식재료 수 / 관리 대상 수 × 100. 반복 변경은 한 번만 집계한다.
- 관리점수: 반올림 전 소비율 × 0.7 + 관리율 × 0.3을 계산하고 최종 정수로 반올림한다. 등급 경계는 90/75/60/40점이다.
- 등록·상태·보관 변경·일부 소비·소비 완료·폐기 이력을 별도 로컬 로그에 보존한다. 원래 냉장고/주간 리포트 저장 형식을 유지한다.
- 한국 시간 월요일/매월 1일 기준으로 기간을 나눈다. 비율과 건수는 즉시 갱신한다.
- 점수는 최근 한국 시간 오전 6시까지의 기록으로 최초 실행 시 계산하여 고정한다. 앱 실행 중 30초마다 및 화면 복귀 시 다음 갱신 시점을 확인한다. 닫힌 브라우저에서 서버 배치는 실행되지 않는다.
- 이전 등록일이 없는 삭제 이력은 처리일 기준으로 복원하고 안내한다. 기록되지 않은 과거 관리 행동·구매/금액은 만들지 않는다. 손상된 신규 로그/점수 캐시는 덮어쓰지 않는다.
- 관리점수의 기준 시각과 실시간 관리율을 화면에 표시한다. 오늘 오전 6시 이후 행동은 다음날 점수에 반영된다.
